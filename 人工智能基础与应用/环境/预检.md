# 会话预检（脚手架区 B7）· 每次开 Kaggle / Colab / 本地 GPU 前跑一遍

> 目的：**在花掉配额之前**发现"这个会话是废的"。历史上最贵的浪费不是训练太慢，
> 而是拿 P100 跑 Triton（SM60 不支持，代码根本跑不起来，却发现时已烧掉半小时）。

## 一、开 Kaggle 后的 30 秒预检（逐条确认）

```bash
# 1) GPU 型号 —— 唯一的一票否决项
nvidia-smi --query-gpu=name,memory.total,compute_cap --format=csv

# 2) 门禁判定
#    Tesla T4 (cc 7.5)      → ✅ 全部课题可跑（fp16 + GradScaler）
#    2 × Tesla T4           → ✅✅ 课题04/06/08/09/10 的多卡实验可跑
#    Tesla P100 (cc 6.0)    → ❌ 立刻重开会话（Triton 不支持；nanochat 会自动降级 fp32 慢 3–5 倍）
#    A100/H100/L4 等        → ✅ 更好，按同样流程跑

# 3) 磁盘与内存
df -h /kaggle/working | tail -1     # 需要 ≥15GB 可用
free -g | head -2                   # 内存

# 4) 依赖自检
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.device_count())"

# 5) 计时器（强制自停）
#    训练脚本必须带 wall-clock 上限，默认 3 小时；Kaggle 会话上限 9–12h，留足保存时间
```

## 二、门禁规则（照做，不许"先跑跑看"）

| 型号 | 允许的课题 | 说明 |
|---|---|---|
| **T4 ×1** | 05（Triton）、07（数据）、01–03（CPU 亦可） | fp16 + GradScaler（T4 无 bf16） |
| **T4 ×2** | 04、06、08、09、10 | DDP 走 PCIe；**扩展效率低是预期现象，不是 bug**（正好是课题06 的教学素材） |
| **P100** | 无 | 立即重开会话 |
| 其他 ≥2 卡 | 同上，按显存调 `--device-batch-size` | 记得同步更新 `章程与地图/算力与成本预算.md` |

## 三、开场三件事（顺序不能反）

1. **写实验卡**（模板见《算力与成本预算.md》§五）→ 交用户确认 → 才允许开跑。
2. **先跑冒烟**：极小规模（如 `--depth=4`、100 步）确认脚本能跑通、能存盘、能续训。
3. **确认产物落地**：checkpoint 写 `/kaggle/working`（持久），日志与曲线随会话导出。

## 四、收尾三件事（关会话前）

1. 记录：日期 / 平台 / GPU 型号 / 实际耗时 / 配额消耗 → 写进 `memory/PROGRESS.md` 算力账本。
2. 归档：`证据/run.yaml` + 日志 + 曲线 + 产物哈希（`环境/归档/` 脚本一键生成）。
3. 释放：确认会话已停止（Kaggle 后台运行也会吃配额）。

## 五、数据搬运（Kaggle 特有）

- 训练语料走 **Kaggle Dataset**（上传一次，每次会话挂载，不重复下载）；
- 小样本（≤几 MB）可进仓库 `资料原件/`，大文件一律不进 git（见学科根 `.gitignore`）；
- ⚠️ 不要引用 `HuggingFaceFW/fineweb` / `huggingface/fineweb`（2026-09-17 实测均 404）。
