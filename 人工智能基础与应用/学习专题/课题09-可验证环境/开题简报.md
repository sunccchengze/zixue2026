# 课题09 开题简报 · 可验证环境 + harness

> 模块：**M7/M8** ｜ 周次：**W13（12-07→12-13）** ｜ 算力：**T2 Kaggle 2×T4，计划 6 GPU·小时**
> 唐杰作业对应：**⑤ 搭可验证环境 + harness** ｜ 判分来源：**自建**（判定逻辑单测 + rollout 成功率）
> 手写：**R9（判定逻辑 / verifier）**

## 一、研究背景

2026 年的关键词是"**可验证奖励**"：与其训练一个会拍马屁的奖励模型，不如**造一个能判定对错的环境**。
CS336 没有这一环，Berkeley Agentic AI MOOC 专门有一讲叫 "Post-Training Verifiable Agents"，
`PrimeIntellect-ai/verifiers` 把它抽象成库。唐杰作业⑤要求"搭可验证环境 + harness"正是这个方向。

**"可验证"的三要素**：①任务是可判定的（不是主观好坏）②环境能给出稳定反馈 ③harness 能重复运行并复现。

## 二、研究问题

> **我能为一个小模型设计一个"可自动判定"的任务环境吗？判定逻辑的假阳性/假阴性有多高？模型在这个环境里的成功率是多少？**

## 三、攻关线索

1. **选题**：从三个里选一个（按成本从低到高）
   - ①**数学题解答**（用数值比对 + 容错；MATH-500 风格）
   - ②**函数补全**（隐藏单元测试；本质是迷你 HumanEval）
   - ③**格式约束生成**（如严格 JSON / 表格填充，规则判定）
2. **判定逻辑的三大坑**：等价但不相同（`1/2` vs `0.5`）、解析失败当错、**边界用例漏判**
3. **假阳性检测**：人为构造"错误但能骗过判定器"的答案 → 测出**假阳性率**（这是质量的核心指标）
4. **harness 设计**：任务装载 → 模型生成 → 判定 → 记录轨迹 → 复现（固定种子）
5. **可重复性**：同一批任务跑两次，成功率波动多大？（**误差棒思维**，M7 讲过）
6. **对照**：可验证奖励 vs 规则弱判定（如只看格式），用同一模型比成功率差异

## 四、里程碑

- [ ] M1 选定任务类型，写 30–100 道题的**题集**（含标准答案与判定规则）
- [ ] M2 **判定逻辑单测**：等价形式、边界、异常输入（≥10 个用例）
- [ ] M3 **假阳性实验**：构造 10 个"错误但可能蒙混"的答案，测出漏判率
- [ ] M4 harness 跑通：给基座模型跑一遍，得成功率 + 失败样本
- [ ] M5 失败分类：把失败归成 3–5 类（格式错 / 计算错 / 中途放弃 / 判定器误杀）
- [ ] M6 一页报告：**判定器质量 + 模型表现 两个都要报**

## 七、代码级提问示例

1. 你的判定器把 `1/2` 判错、把 `0.50` 判对——这属于哪一类错误？如何系统性避免？
2. 假阳性率高会导致 RL 训练出现什么后果？（联系课题08 的 reward hacking）
3. 同一批任务两次运行成功率差 8%。你会先怀疑模型还是 harness？怎么验证？
4. 为什么"用 LLM 当裁判"在可验证任务上通常是**退步**？

## 八、风险与提醒

- ⚠️ **判定器本身也要被评测**：只报模型成功率不报判定器质量，是不完整的实验。
- ⚠️ 题集不要抄公开 benchmark（污染问题），**自己出题 + 自己判定**才是本课题的价值。
- ⚠️ 配额有限：优先"题集质量高、任务简单"，不要一上来做代码执行沙箱（那是课题10 的事）。
