# 课题04 开题简报 · 0.1B 端到端预训练（**首次上机**）

> 模块：**M4/M5** ｜ 周次：**W5–W6（10-12→10-25）** ｜ 算力：**T2 Kaggle 2×T4，计划 12–21 GPU·小时**
> 唐杰作业对应：**① 端到端训一个 0.1B** ｜ 判分来源：**自建**（loss/bpb 达标 + 采样可读性）+ `nanochat/core_eval.py` 的 CORE
> 手写：复用课题01/02 的产物（tokenizer + 模型 + 优化器），本课题新增**数据管线与训练编排的判断**

## 一、研究背景

"0.1B" 是唐杰作业里的数字，也是**单卡/双卡免费算力下的上限**。参考点：nanochat 的 d12 约等于 GPT-1 量级
（官方讨论区原话："d12 是我最喜欢的模型，它是 GPT-1 的大小，约 6 分钟训完"——那是在 8×H100 上）。
**本课题的核心不是刷指标，而是把"训练一次完整模型"的每个环节亲自走通并记账。**

## 二、研究问题（一句话）

> **在 2×T4、20 GPU·小时的预算内，我能不能从零训出一个"能生成连贯英文、并在 CORE 上有非零分"的 0.1B 模型？实测成本与估算差多少？**

## 三、攻关线索

1. **数据**：TinyStories（全量）+ owt-sample 采样。**先算一遍**：词表大小 × 语料字节 → token 数 → 需要的步数
2. **规模选择**：nanochat 用单一旋钮 `--depth`；在 T4 上 16GB 显存能放多深？（用 M0 的显存公式先估）
3. **精度**：**T4 是 SM75，没有 bf16** → 必须 fp16 + GradScaler（或用 nanochat 的 `NANOCHAT_DTYPE=float16`）
4. **断点续训**：Kaggle 会话 9–12h 会断 → checkpoint 必须写 `/kaggle/working`（20GB 持久）
5. **超时自停**：脚本内置 wall-clock 上限，防止忘记关会话
6. **指标**：训练看 bpb（词表无关），最终跑 CORE（22 数据集合成，`core_eval.py` 单文件）

## 四、里程碑

- [ ] M1 **实验卡获批**：写清假设/命令/预算上限/停止条件/成功判据（见《算力与成本预算.md》§五）
- [ ] M2 **会话预检**：`nvidia-smi` 确认 2×T4（**若是 P100 立即重开会话**）
- [ ] M3 **冒烟**：`--depth=4`、100 步，确认能跑、能存、能续训（≤10 分钟）
- [ ] M4 首次正式训练：双 T4 + DDP，跑到预算上限或 loss 平台
- [ ] M5 续训一次（验证 checkpoint 真的可用 —— 这一条最容易翻车）
- [ ] M6 评测：bpb + CORE + **采样 20 条样本**（人工判断"是否连贯"）
- [ ] M7 **成本账单**：实测耗时 vs 估算（M0 的 6ND + T4 折算），逐项解释偏差
- [ ] M8 一页报告 + 知识卡（含"我最意外的三个现象"）

## 八、风险与提醒

- 🚨 **P100 陷阱**：本课题如果拿到 P100，训练慢 3–5 倍且后续课题05 直接不可用 → **宁可等 T4 时段**。
- 🚨 **配额**：本课题占全学期约 1/5 的配额，实验卡必须写实；**冒烟不通过不许开正式训练**。
- ⚠️ 0.1B 在 T4 上大概率需要"降 batch + 梯度累积"，这会改变有效 batch size → **要写进 run.yaml**。
- ⚠️ Kaggle 会话到期会杀进程：**每 500 步存一次**是硬要求。
