# ERRORS · 判例库

> 结构：**通用红线**（导师纪律，只读继承区，来自概率论与全仓大扫除沉淀）
> + **本学科判例**（用户错误 / 导师越界，每条带"红线"）。

## 通用红线（只读继承区，不许改）

1. 判卷前先完整还原用户算式；写法不同 ≠ 错。
2. 指数/上下标逐字符放大核对；看不准就定点请用户确认，不许凭印象判。
3. 思考旁白/括号吐槽/口误不算答案；只看最终结论与论证。
4. 宣布"通过"必须附证据引用（哪套卷、哪个正确率、哪些 leech 清零）。
5. 出题不得含答案或答案形状的例子；难度分档 A/B/C，综合卷 A 档 ≤20%。
6. 输入双通道：手写照直接读图；文字输入警惕语音同音误识别（语义通顺优先按正解接收并标"语音锅"）。
7. **引用的数字必须先复现**（如 GPU 价格、stars、耗时），不许照抄印象值。

## 本学科判例

### 导师越界类（预防性记录，2026-09-17 立）

- **E-01 · 手写区写入**：Agent 往 `课题NN/手写/` 写入实现文件——即使内容正确也算违规。
  **红线**：手写区内我只读、只评论；违规后必须自行删除改判为"审查意见 + 测试建议"。
- **E-02 · 指路第三方实现**：说"你可以参考 nanochat 的 `flash_attention.py` 第 30 行"。
  **红线**：只允许指出该功能在架构中的**位置与接口契约**、以及官方讲义章节；不得指向具体行当答案。
- **E-03 · 跳过实验卡烧配额**：没等用户确认实验卡就开跑 GPU。
  **红线**：任何付费/配额消耗前必须经用户确认（哪怕只回一句"跑"）。
- **E-04 · 把"讲了"当成"学了"**：讲完概念直接进下一个知识点，没出代码级提问、没跑实验。
  **红线**：四件咬合（讲/做/证/反）缺一即标 🟡，不许标 ✅。

### 用户判例类（待实战填充）

- ⬜ 暂无。本学科的"错误"形态将与其它学科不同——预期是**预测错**（这不算错误，是资产）
  与**无预测就跑实验**（这算错误）。首次实战后按此格式记录：
  `[日期] 现象 → 根因 → 红线（下次先问什么）`。

### 环境类判例（踩坑记录，**均为 2026-09-17 实跑实测**）

- **E-05 · 官方判分器需要 Python ≥3.12**：CS336 2026 的 `tests/conftest.py` 使用 PEP 695 泛型语法
  （`def f[T](...)` / `class C[T]`），`pyproject.toml` 写死 `requires-python = ">=3.12,<3.14"`；
  沙箱为 Python 3.11.2，**解析即报 SyntaxError**。
  **处置**：3.11 下自动改用等价轻量 conftest（保留同一 `snapshot` 夹具语义），并在判分日志头部声明；
  升到 3.12+ 自动切回官方原文。**红线**：不许为了让测试跑起来去改官方 `test_*.py`。
- **E-06 · tiktoken 对齐测试需要外网**：`test_*_matches_tiktoken` 共 12 项依赖 tiktoken 的 GPT-2 编码器，
  首次使用会联网下载 `openaipublic.blob.core.windows.net` 上的 vocab.bpe / encoder.json；
  沙箱该域名 SSL 被拦 → 12 项测试报 `requests.exceptions.SSLError`（**看起来像代码错，其实是网络**）。
  **处置**：`环境/judge/prefetch_tiktoken.py` 用官方 fixture 离线构造缓存
  （实测 `gpt2_vocab.json` 的 sha256 与 tiktoken 内置期望**完全一致**；vocab.bpe 补 `#version: 0.2` 首行即可，
  因 tiktoken 解析时 `split("\n")[1:-1]` 跳过首行且对 gpt2 不校验哈希）。验证：n_vocab=50257、往返一致。
  **红线**：判分失败先分辨"代码错 / 环境错"，不许把环境问题记成用户错误。
- **E-07 · PyTorch CPU 专用源被拦**：`download.pytorch.org` 在沙箱返回 SSL EOF；
  PyPI 上的 torch 是 555MB 的 CUDA 版（连带依赖数 GB，而沙箱内存仅 3GB）。
  **处置**：T0 档默认**不装 torch**（课题01 判分确实不需要），需要时 `--with-torch` 先试 CPU 源再退回 PyPI。
- **E-08 · Kaggle 可能分配 P100**：P100 计算能力 6.0，**Triton 不支持**（要求 ≥7.0），
  且 nanochat 在 SM<80 下自动降级 fp32（慢 3–5 倍）。**红线**：课题05 开跑前必须验明 GPU 型号，P100 立即重开会话。


### E-09 沙箱无 LaTeX / 无 Chromium / **无任何中文字体** / 中国镜像全不可达（2026-09-17 实测）
- **判据**：`xelatex/pdflatex/wkhtmltopdf/chromium/weasyprint` 全无；`fc-list :lang=zh` 返回 **0 条**；
  清华/中科大/阿里/浙大镜像与 gitee **DNS 均不通**；**可用通道 = PyPI + npm**。
- **处置**：中文 PDF 走「**PyPI 版 typst**（静态链接预编译，`pip install` 即得）
  + **npm 版思源宋体/黑体**（`@expo-google-fonts/*`）」；一次准备（`环境/pdf/bootstrap.sh`），编译全程离线；
  字体与 Python 环境放仓库外 `/home/user/opt/`（不进 git）。
- **教训**：中文排版的第一门槛是**字体**而不是引擎——先问"这台机器有没有 CJK 字形"，再选工具。

### E-10 pandoc 的 typst 数学转写有损 → 弃用
- 实测 `\langle x,y \rangle` 被改写为 `(x, y)`（尖括号语义丢失）；表格/emoji/代码块样式不可控。
- **处置**：自研 `环境/pdf/md2typst.py`，并立铁律**未知 LaTeX 命令直接报错、绝不静默丢公式**。
- **教训**：公式是讲义的知识锚点，**转换损失比转换报错危险得多**。

### E-11 typst 的四个静默陷阱（会吃掉内容，比报错更危险）
| 陷阱 | 现象 | 处理 |
|---|---|---|
| `//` 与 `/*` 是注释 | 路径 `证据/*.yaml`、`讲义/*.md` **后面的正文被静默吞掉** | `/` 后紧跟 `*` 或 `/` 时写成 `\/` |
| `@` 是引用语法 | `@expo-google-fonts` → ``label `<expo-google-fonts>` does not exist`` | 写 `\@` |
| **连写字母 = 一个标识符** | 数学里 `xy`/`QK`/`argmax`/`times12` 全报 unknown variable | 片段拼接时在字母数字相邻处补空格 |
| `*…*` 强调有边界歧义 | `③*bpb 会变吗？*` 报 `unclosed delimiter`（中文文本里极易踩） | 改用函数式 `#strong[..]` / `#emph[..]` |
- **附**：符号"名字"随版本变动（`angle.l` / `dot.circle` / `diff` / `prod` 在 typst 0.15 里**都不存在**）
  → 一律改用**字面 Unicode 字符**（`⟨ ⟩ ⊙ × √ ∂ ∏`），实测在数学模式下稳定可用。
- **教训**：**"能编译"不等于"内容都在"**。

### E-12 排版验收必须自动化（防"悄悄吞内容"）
- 事故：一次手改把封面 `#align(center)[` 的开括号误删，报错只有 `unclosed delimiter`（无行号），排查很久；
  后来发现 typst 绑定的异常对象带 `diagnostic / hints / trace` 字段，**能直接给出 文件:行:列**（有它就不是难题）。
- **处置**：`md2typst.py` 内置三重验收 —— ①**公式逐条单独编译**（M0–M3 共 99 条去重）
  ②二/三级标题**齐备性核对**（含公式的标题只核对公式前那段中文）③页数/体积/`--preview N` 预览图人眼抽检。
- **教训**：①排错先读 `e.diagnostic` 再二分；②**产物型工作必须配自动验收**，否则错误会以"看起来正常"的形式留下来。
