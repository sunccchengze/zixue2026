# 记忆系统 · 人工智能基础与应用 I（课程轨 + 实训轨 + 知识轨）

> 参照技能宝库 `memory-system`（6 引擎架构）与 `self-improving-agent` / `growth-log` 方法，
> 按本学科"**实验型 + 有成本**"的特性做加法。
> 新会话开局第一步必须读完本文件夹，才能做到"零损耗接力"——不用用户重新交代背景。

## 目录结构

```
memory/
├── MEMORY_SYSTEM.md      本文件：架构说明 + 新会话接入协议
├── HANDOFF.md            交接总账本：现在到哪一步、下一步做什么（最重要，永远最新）
├── LEARNINGS.md          学习画像：偏好、卡点、已验证有效的讲法
├── ERRORS.md             判例库：导师纪律红线 + 用户判例（每条带红线）
├── MEMORY.md             当前理解主账本：核心直觉 + 预测→打脸→修正日志（只增不改流水）
├── PROGRESS.md           11 课题台账 + **算力账本** + 课程轨台账
└── drill-ledger/         drill-me 式间隔重复卡片账本
    ├── index.md
    └── topics/topicNN-<知识点>.md
```

## 新会话接入协议

0. 先读仓库根 `AGENTS.md`（回合级 commit+push；输入双通道规则）。
1. 读 `HANDOFF.md`——上次卡在哪、下一句该问什么。
2. 扫 `LEARNINGS.md` 与 `ERRORS.md`——避免用验证过没用的讲法、避免踩过的坑。
3. 查 `PROGRESS.md`——11 课题在第几站，**以及算力账本本周还剩多少小时**。
4. 查 `drill-ledger/index.md`——有没有到期该复习的卡片（欠账优先）。
5. 确认本轮属于 `手写/` 还是 `脚手架/`（《造轮子边界.md》），属于 M0–M9 哪个模块（《知识地图》）。
6. 开场不重新自我介绍、不重讲规则，直接从"接着上次"的地方问问题。

## 六个引擎在本学科的落地

| 引擎 | 落地方式 |
|---|---|
| self-improving-agent | 用户被问倒/纠正我的讲法 → 写 `LEARNINGS.md`；我的越界 → 写 `ERRORS.md` |
| three-layer-memory | L1 当轮对话临时上下文；L2 `ERRORS.md` 判例；L3 `PROGRESS.md` + `drill-ledger` 长期状态 |
| memory-entropy | 每 5–8 次对话清理过时条目，保持精炼 |
| memory-evaluator | 每次审报告前先对照 `ERRORS.md` 自查 |
| precedent-memory | `ERRORS.md` 每条误区=判例，之后直接引用判例名 |
| learning-system | 本文件——调度以上文件的读写时机 |

## 本学科新增的两个账本（其它学科没有）

1. **算力账本**（在 `PROGRESS.md`）：日期 / 平台 / GPU 型号 / 耗时 / 本周累计 / 余量。
   规矩：跑完当场记，不隔夜；不记账 = 不许开下一次实验。
2. **预测—打脸日志**（在 `MEMORY.md`）：本学科的核心学习机制是"**先预测 → 跑实验 → 修正直觉**"，
   所以每个课题至少要有一条"我以为是 X，实测是 Y，因为 Z"。**预测错不算失败，没有预测算失败。**

## 记忆熵降噪规则

- `LEARNINGS.md` / `ERRORS.md` 单文件超过约 150 行时做一次合并（同根因合并，先搜有没有旧条目）。
- 只记**可迁移的模式**，不记流水账。
- 知识点的细粒度记忆一律进 `drill-ledger/topics/`，不在主账本堆概念。

## 与其它文件的关系

- 教学法：`章程与地图/知行合一规程.md`；谁写代码：`造轮子边界.md`；学什么：`知识地图-大模型全景.md`
- 本学科的 `MEMORY.md` 允许出现**代码片段级**的直觉（"为什么这里要 detach"），
  这与其它学科以公式为主不同——因为本学科的知识点必须能落到代码位置。
