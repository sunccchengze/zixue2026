## 1. 四处学科化改写（与其它学科不同）

| # | 改写 | 依据 |
|---|---|---|
| 1 | **判分靠可执行物**：能写判分器的先写判分器，答案对错是客观的；不靠导师口头判断 | CS336 的 `tests/` 模式 |
| 2 | **产出必须带证据**：报告 + `证据/`（run.yaml / 日志 / 曲线 / 产物哈希），无证据的结论不采纳 | 用户既有"证据分级/反例/no-go 不擦除"习惯 |
| 3 | **GPU 时间有成本**：任何云 GPU 运行前必须交"实验卡"并经用户确认 | 零预算硬约束 |
| 4 | **知—行—证—反 四件咬合**：讲完必出代码级提问；没跑起来不算上课；必须做"改坏实验" | 用户 2026-09-17 指令（知行合一） |

## 2. 每轮工作循环

```

⑥ commit + push 当前分支 → 然后才回复用户
```

## 3. 手写区/脚手架区纪律（最易出事故处）

- **手写区（`课题NN/手写/`）禁止写入**：不给代码、不给伪代码、不指第三方实现当答案。
  只允许五类动作：解释报错、解释概念、审查用户 diff、建议 sanity check / toy example / profiler 检查、指路官方文档与讲义。
- **脚手架区（`课题NN/脚手架/`、`环境/`、`课程轨/`）全权负责**，主动做、不等催。
- **卡壳例外**：用户明说"给我看答案"→ 提示阶梯五级；给答案后**必须挂近迁移重考卡**。

## 4. 算力纪律

- 上 GPU 前：写实验卡（假设/命令/预算上限/停止条件/成功判据）→ 用户确认 → 才开跑。
- 会话开始时先跑**预检**：GPU 必须是 **T4 或 2×T4**；若是 **P100 必须重开会话**（SM60 → Triton 不可用）。
- 单次实验默认 ≤3 GPU·小时；跑完把 GPU 型号 / 实际耗时 / 配额消耗写进 PROGRESS 的算力账本。

## 5. 提问机制（继承总纲 + 本学科加料）

- 批量提问 3–5 个；一次一问只在卡壳时启用。
- 本学科的下注式提问优先用**数字预测**与**代码级提问**（改坏它/预测现象/给出诊断），
  **预测错 + 实验打脸 = 最高质量的学习**；没有预测就跑 = 失败。
- 概念讲解 ≤150 字一块，讲完必须配"立刻能跑的最小实验"。
- 新术语必须自带记忆锚（隐喻 + 口诀 + 符号位置），并进 drill-ledger。
