## 一、自动微分：为什么反向传播只要一遍

**计算图**：把 $f(x_1,\dots,x_n)$ 表示为有向无环图，每个节点是一次基本运算。
**链式法则**：若 $y = f(g(x))$，则 $\frac{dy}{dx} = \frac{dy}{dg}\cdot\frac{dg}{dx}$。

两种方向的差别（这是本讲的**第一个关键直觉**）：

| 模式 | 做法 | 成本 | 适合 |
|---|---|---|---|
| 前向模式 | 从输入往输出推导数 | 每个输入要一遍 → **n 遍** | 输入少、输出多 |
| **反向模式** | 从输出往输入推导数 | **一遍**拿到全部输入的偏导 | **输入多、输出少 ← 我们的情况** |

我们的情况是"几亿个参数（输入多）→ 一个标量 loss（输出少）"，
所以**反向模式（就是我们说的反向传播）**是天选：**1 次前向 + 1 次反向 = 全部梯度**。

**梯度累加的工程含义**：反向时每个节点把上游梯度**相加**。这解释了两个常见现象：
①同一个张量被用了两次（如权重共享），梯度会累加；
②既然梯度是"累加"的，就能**梯度累积**（gradient accumulation）——多个小批次的梯度加起来等价于大批次，
这是后来显存不够时的核心手段（课题04 会用到）。

**在代码里长什么样**：
- `手写/` 里会有一个 `Value` 类（或等价的张量自动微分），核心是 `.backward()`：
  按**拓扑逆序**遍历，每个节点用局部导数乘上游梯度累加到父节点。
- 上游对照：`nanochat/optim.py` 里参数更新前的 `p.grad` 就是这一机制的产物；CS336 A1 的
  `run_gradient_clipping` 则是**在使用**梯度（先要能算出来）。

## 二、信息量、交叉熵、困惑度、bpb（**跨分词器可比性**的根源）

**信息量**：一个概率为 $p$ 的事件携带的信息是 $-\log p$（nats，底为 $e$；若底为 2 则单位是 bit）。

**熵**：随机变量的平均信息量 $H(p) = -\sum_x p(x)\log p(x)$。
直觉：**"平均每个符号有多难猜"**。

**交叉熵**：用模型分布 $q$ 去编码真实分布 $p$ 的代价
$$H(p,q) = -\sum_x p(x)\log q(x)$$
语言模型里 $p$ 是"真实下一个 token"，$q$ 是模型输出 —— **这正好就是训练 loss**。

**困惑度**：$\mathrm{PPL} = \exp(H(p,q))$（nats 为底时）。
直觉最有用的一句话：**"模型平均在多少个等概率选项里犯迷糊。"** PPL=10 相当于"平均 10 选 1"。

**bpb（bits per byte）**：
$$\mathrm{bpb} = \frac{H(p,q)\ \text{[nats]}}{\ln 2 \times \overline{\#\text{bytes per token}}}$$
分母是"平均每个 token 对应多少字节"。

> **为什么必须用 bpb 跨模型比较**：交叉熵的单位是"每 token"，而 token 的大小随分词器变化——
> 词表越大 token 越"大"，同样文本的 token 数越少，单 token 交叉熵天然越高。
> **除以"每 token 字节数"就把记账单位统一到"每个字节"上，于是与分词器无关。**
> 这也解释了 M2 讲义的结论：换词表后 loss 不可比，bpb 可比。

**在代码里长什么样**：`nanochat/loss_eval.py` 专门做 bpb（而不是 loss）的评估；
`nanochat/core_eval.py` 则是另一类指标（CORE，由 22 个数据集的准确率合成）。
**你在课题01 的压缩率表，其实是在预演 bpb 的分母**——先感受"每 token 多少字节"。

## 三、算力与显存记账（**估数量级**是核心能力）

**参数量**（Transformer 主项，细节见 M3）：
- 每层注意力 $4d^2$（Q/K/V/O 四个 $d\times d$），MLP 约 $8d^2$（SwiGLU 的等价形式）→ **每层 ≈ $12d^2$**
- 词嵌入 $V\cdot d$（权重共享时 1 份）

**算力（训练）**：业界通用估算
$$\text{总 FLOPs} \approx 6 \times N \times D$$
其中 $N$ 是**非嵌入参数量**，$D$ 是训练 token 数。拆解：每个参数在前向贡献 2 FLOPs（乘+加），
反向是前向的 2 倍 → 合计 6。注意力部分另有 $12 L h q t$ 项（序列长度相关，短序列时可忽略）。
> Karpathy 在 nanochat 文档里给的就是这个公式，并特别注明"与 Chinchilla 略有 1% 差异，因为不计嵌入与 softmax"。

**显存（训练）**：粗算每参数
| 项 | 字节数 |
|---|---|
| 参数（bf16） | 2 |
| 梯度（bf16） | 2 |
| Adam 一阶动量（fp32） | 4 |
| Adam 二阶动量（fp32） | 4 |
| **小计（不含激活、不含 fp32 主权重）** | **≈ 12–16** |
| 激活（随 batch × 序列长度增长，可用 checkpointing 换） | 视配置 |

**练习式直觉**：0.1B 参数 × 16 字节 ≈ 1.6GB（优化器+梯度+权重）；
剩下的全是激活与临时张量 —— **这就是为什么 16GB 的 T4 训 0.1B 要精打细算**（课题04 的真实约束）。

**在代码里长什么样**：`nanochat/gpt.py` 里有 `estimate_flops()` 与 `num_scaling_params()` 两个方法，
正是上面两段公式的代码化。**课题03 的 scaling law 就是靠这两个函数把"跑多大"换算成"花多少算力"的。**

## 四、数值稳定性：softmax 与 logsumexp

**问题**：$\mathrm{softmax}(x)_i = e^{x_i}/\sum_j e^{x_j}$。若某个 $x_i = 1000$，$e^{1000}$ 直接溢出成 `inf`。

**解法**：分子分母同乘 $e^{-m}$（$m=\max_j x_j$）：
$$\mathrm{softmax}(x)_i = \frac{e^{x_i-m}}{\sum_j e^{x_j-m}}$$
数值上完全等价，但最大指数变成 $e^0=1$，永不溢出。**"减最大值"不是技巧，是恒等变形。**

**logsumexp 技巧**：$\log\sum_j e^{x_j} = m + \log\sum_j e^{x_j - m}$，
这是所有"用 log 概率做加法"的算法（交叉熵、CTC、HMM、flash attention 的 online softmax）的共同基础。

**为什么这很重要**：课题05 的 **online softmax** 就是"分块计算时如何边算边保持数值稳定"，
其思想内核与这里的减最大值完全一致——**你在 M0 学的东西，会在 Triton kernel 里原样再出现一次。**

## 五、"loss 不降"的排查顺序（把知识变成动作）

1. **数据**：label 与输入错位了吗？分词是否正常（看打印出来的样本）？
2. **初始化**：全零/全同初始化会让对称性无法打破；检查 std 与层数是否匹配
3. **学习率**：太大 → loss 震荡/NaN；太小 → 曲线是平的。先用小数据**能否过拟合一条样本**自检
4. **形状与 mask**：mask 是否在 softmax 之前施加？是否广播到正确维度？
5. **数值**：是否出现 `inf/nan`？打开梯度范数监控
6. **数值精度**：bf16 在小模型/小梯度上可能不够（T4 没有 bf16，课题04 要用 fp16 + GradScaler）

> 这份顺序本身就是"知行合一"：**它会成为课题04 的排查清单**，而不是一段可背诵的文字。

## 六、能立刻跑的实验

```bash
# ① 手算 bpb 的换算（先自己推，再看输出对不对）
环境/.venv/bin/python - <<'PY'
import math
# 假设某模型：每 token 交叉熵 2.0 nats，平均每个 token 对应 4 个字节
loss_nats, bytes_per_token = 2.0, 4.0
ppl = math.exp(loss_nats)
bpb = loss_nats / math.log(2) / bytes_per_token
print(f"loss={loss_nats} nats → PPL={ppl:.2f}, bpb={bpb:.3f}")
print("→ 再推一遍：若词表翻倍使 bytes/token 变成 6，bpb 会怎么变？loss 呢？")
PY

# ② 验证"减最大值"是恒等变形（含极端值）
环境/.venv/bin/python - <<'PY'
import numpy as np
x = np.array([0.0, 1000.0, 1000.0])
naive = np.exp(x) / np.exp(x).sum()      # 溢出
stable = np.exp(x - x.max()) / np.exp(x - x.max()).sum()
print("naive :", naive, " ← 溢出成 nan")
print("stable:", stable, " ← 正确")
PY
```

## 八、记忆锚

- **隐喻**：反向传播 = **"责任回溯"**——loss 是最终事故，每个参数按"它贡献了多少"分摊责任；
  责任可以累加，所以梯度能攒（梯度累积）。
- **口诀**：**"一遍反向、六倍算力、十六字节、先减最大值"**
  （反向传播一遍 / 6ND / 每参数约 16 字节 / softmax 稳定性）
- **符号位置法**：把 $\mathrm{bpb} = \dfrac{H}{\ln 2 \cdot B}$ 写在卡片中央，
  **分子 H 是"每 token 的惊讶"，分母 B 是"每 token 的字节"**，
  中间一条分数线＝"把单位从 token 换成 byte"——这条线就是跨分词器比较的桥。
