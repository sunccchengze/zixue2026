# 讲义库 · 使用方法（三师制里的"我"那一腿）

> 立库 2026-09-17。**为什么要有这个库**：用户指出"实操性够强，但知识讲解偏少"。
> 《知识地图》回答"学什么"，《对标资源清单》回答"跟谁学"，
> **本库回答"此刻这一讲到底讲了什么"**——由我按你的水平写的**主讲义**。
>
> 三者关系不是替代，是分工：
> - **对标名师**（Raschka / 李沐 / 李宏毅 / CS336）＝ 权威原始讲法，读它打地基
> - **本库讲义** ＝ 为你量身写的浓缩主干 + 与代码的对应 + 常见误解（省你时间）
> - **我（对话里）** ＝ 只讲你卡住的那一层，出代码级提问，判你的理解

## 讲义规范（每讲必含 8 件）

| # | 部件 | 作用 |
|---|---|---|
| 1 | 本讲要回答的 3–5 个问题 | 带着问题读，读完能答才算过 |
| 2 | 主干讲解（≤150 字/概念块） | 一次讲透，不挤牙膏 |
| 3 | 公式/伪代码骨架 | 这是"手写区"的地图，**不是答案** |
| 4 | **在代码里长什么样** | 指向 `手写/` 或上游 nanochat 的**函数与接口**（不给行号、不给实现） |
| 5 | 常见误解（每条配一个反例） | 抄自历届踩坑与官方测试的隐含要求 |
| 6 | 能立刻跑的实验 | 讲完就跑，知行咬合点 |
| 7 | 代码级提问（3–5 道） | 改坏它/预测现象/给出诊断 |
| 8 | 记忆锚（隐喻 + 口诀 + 符号位置） | 进 drill-ledger |

## 使用流程（照做）

```
① 预习：读本讲"要回答的问题"（2 分钟）
② 读对标材料对应章节（≤25 分钟，带着问题读）
③ 读本库讲义（≤15 分钟，看主干与"代码里长什么样"）
④ 合上讲义，用自己的话讲给我听 → 我专挑含糊处追问
⑤ 进手写区（R 类任务）→ 跑判分
⑥ 做"改坏实验"→ 先预测 → 再跑 → 修好
⑦ 我出代码级提问，你作答 → 进 drill-ledger 建卡
```

**纪律**：讲义里**不含可直接粘贴到 `手写/` 的实现**（见《造轮子边界.md》）。
讲义给的是"坐标系 + 陷阱 + 判据"，代码必须你自己长出来。
