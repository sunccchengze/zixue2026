# 知识地图 · 大语言模型全景（M0–M9）

> 立图 2026-09-17。**本文件回答一个问题：要把大语言模型"彻底搞懂"，到底要懂哪些东西。**
> 每个模块都是"**四个咬合件**"：核心问题 → 对标材料 → 亲手实验 → 判分证据。
> 只讲不做 = 没学（见《知行合一规程.md》）；只做不讲 = 学歪。
>
> 用法：模块不是线性章节，但**顺序有依赖**（M0→M1→M2→M3→M4→M5→M6→M7→M8→M9）。
> 每周讲哪个模块，见《实训路线图.md》的"知识讲解锚点"列。

## 判断"真的懂了"的三条硬标准（本学科通用）

1. **能讲清**：不用术语、用大白话讲给外行听，且能回答"为什么不是别的做法"。
2. **能指出代码位置**：说出这个概念在本仓 `手写/` 或上游 nanochat/CS336 里**具体是哪个函数、哪几行**。
3. **能改坏并修好**：故意改坏（去掉 mask、换掉归一化、打乱位置编码）→ **预测**现象 → 跑实验验证 → 修回。
   （第 3 条是"知"与"行"的分界线；只会背定义的人在第三步一定翻车。）

## M0 · 数学与机器学习地基

- **核心问题**：梯度到底怎么传过 100 层？为什么归一化能让训练稳下来？交叉熵、困惑度、bpb 三者的关系是什么？参数量/FLOPs/显存怎么估？
- **关键概念**：链式法则与计算图、雅可比、损失函数（MSE/交叉熵）、梯度下降族、正则化、数值稳定性、信息量与熵、复杂度记账（6ND 公式）
- **对标**：李沐《动手学深度学习》ch2–ch5、ch11（优化算法）；Karpathy micrograd 视频；概率论课题01–08（已建成，直接搭桥）
- **亲手实验**：手写 micrograd（标量自动微分，200 行内）→ 手写 MLP 在 MNIST 子集上训到 >95%
- **判分证据**：与 PyTorch autograd 的数值梯度对照表（误差 < 1e-6）+ 参数量/FLOPs 估算脚本实测偏差
- **常见误解**：把 loss 当"正确率"；以为"梯度消失"是 bug 而不是结构性质；以为 d2l 的 MXNet 代码不用改

## M1 · 语言模型史与前 Transformer 时代

- **核心问题**：Transformer 解决了什么前人的痛点？为什么 attention 取代了 RNN？"语言模型"这个词 20 年里的含义变化？
- **关键概念**：n-gram 与平滑、词袋、word2vec/GloVe、RNN/LSTM/GRU、seq2seq + 注意力、Bahdanau/Luong attention、并行化的动机
- **对标**：李沐 d2l ch8–ch10（RNN → 注意力）；CS336 lecture 01（概览与分词）；《Attention Is All You Need》原文（入论文精读）
- **亲手实验**：手写 bigram/trigram 语言模型算困惑度 → 手写一个最小 RNN LM → 对比同参数量的单层 Transformer
- **判分证据**：三者在同一语料上的 bpb 对照表 + "RNN 为什么慢"的显式计时（逐步 vs 并行）
- **常见误解**：以为"注意力=Transformer"；以为 attention 是 2017 才发明的（其实 2014 就有）

## M2 · 分词与表示

- **核心问题**：为什么不用字符？为什么不用整词？词表大小怎么权衡？中文/代码/数学符号怎么处理？
- **关键概念**：BPE（训练循环、merge 规则、特殊 token、bytes 回退）、WordPiece、Unigram、词表大小 ↔ 序列长度 ↔ 参数量的三方权衡、压缩率
- **对标**：CS336 A1 tokenizer 部分；nanochat `tokenizer.py`；HF LLM Course ch2（"Implement BPE/WordPiece/Unigram from the ground up"）
- **亲手实验**：手写 BPE（训练 + 编码 + 流式编解码往返）→ 在 TinyStories 与中文语料上各训一个词表 → 测压缩率
- **判分证据**：`tests/test_tokenizer.py`、`test_train_bpe.py` 全绿 + 压缩率表（中英文分别）+ 往返一致性
- **常见误解**：以为 token 就是"词"；忽略中文一个汉字可能被切成 2–3 个 byte token 导致实际序列变长

## M3 · Transformer 架构与内部机制

- **核心问题**：attention 到底在算什么？为什么需要多头？位置编码为什么从正弦换成 RoPE？RMSNorm 凭什么比 LayerNorm 更常用？残差在防什么？
- **关键概念**：QKV 与缩放点积、因果 mask、多头与 GQA/MQA、RoPE（含外推）、RMSNorm、pre-norm vs post-norm、FFN/SwiGLU、权重共享、初始化与 QK-norm、参数量分解
- **对标**：CS336 lecture 03–04 + A1 model 部分；rasbt《LLMs-from-scratch》ch3–ch4（含 MoE/GQA/MLA/SWA 附录）；李宏毅 GenAI-ML；nanochat `gpt.py`
- **亲手实验**：手写完整 Transformer 层（含 RoPE/RMSNorm/SwiGLU）→ 形状测试 → **改坏实验**：去掉因果 mask、把 RoPE 换成可学习位置嵌入、去掉残差，各跑一次看现象
- **判分证据**：`tests/test_model.py`、`test_nn_utils.py` 全绿 + 三组"改坏"实验的 loss 曲线与现象记录（进 `证据/`）
- **常见误解**：以为 attention 是"可解释的检索"；以为参数越多越好；忽略 pre-norm 对稳定性的决定性作用

## M4 · 训练：数据、优化、系统

- **核心问题**：为什么同样的模型有人训得动有人训崩？Scaling law 怎么指导算力分配？多卡为什么不是线性加速？
- **关键概念**：预训练目标与数据配比、去重与过滤、AdamW（解耦权重衰减）、Muon、LR schedule（warmup+cosine）、梯度裁剪、混合精度（bf16/fp16/fp32 与 GradScaler）、梯度累积、DDP/FSDP/TP/PP、通信开销与扩展效率、Chinchilla 与 compute-optimal、`--target_flops`
- **对标**：CS336 A2/A3 + lecture 05–11；nanochat `optim.py`/`base_train.py`/`runs/scaling_laws.sh`；HF Ultra-Scale Playbook（分布式，待核）；李沐 d2l ch11–ch12
- **亲手实验**：手写 AdamW 与 LR 调度 → 单卡固定算力下的 depth sweep（d4/d6/d8/d10）→ 拟合幂律外推 d12 → **用真实 d12 训练验证预测（打脸链路）** → 双卡 DDP 测扩展效率
- **判分证据**：`tests/test_optimizer.py` 全绿；sweep 原始数据 + 拟合图 + 外推预测存档（**预测先写死再跑**）；扩展效率曲线 + 通信占比
- **常见误解**：以为"loss 不降就是数据问题"；把显存不足当成硬件不够（其实是批大小/精度/累积没调）；把 DDP 当免费加速

## M5 · 推理与部署

- **核心问题**：为什么生成是逐个 token 的？KV cache 省了什么、代价是什么？量化会掉多少点？吞吐与延迟怎么权衡？
- **关键概念**：自回归解码、KV cache、批处理与 continuous batching、PagedAttention、采样策略（temperature/top-p/top-k）、量化（int8/int4/GPTQ/AWQ）、投机解码、显存占用分解、token 成本
- **对标**：nanochat `engine.py`（KV cache 实现）+ `infer_bench.py`；CS336 lecture 10（Inference）；rasbt ch2（生成与 KV caching）
- **亲手实验**：从零写 KV cache 的自回归生成 → 对比有无 cache 的耗时/显存 → 手写一个贪心 vs top-p 采样对照 → 测不同 batch size 的吞吐
- **判分证据**：`tests/test_engine.py` 全绿 + 延迟/吞吐/显存三张图 + "cache 换来多少倍加速"的实测数字
- **常见误解**：以为推理慢是因为"模型太大"（常是没批处理/没 cache）；以为量化无损

## M6 · 后训练：从"会说话"到"会做事"

- **核心问题**：SFT、DPO、RLVR 各自在补什么能力？为什么 RLVR 能提升数学/代码却可能伤害通用能力？reward hacking 长什么样？
- **关键概念**：指令微调与 chat template、损失掩码（只算 answer 部分）、奖励模型、PPO、DPO 的隐式奖励、GRPO 的组内归一化优势、可验证奖励（verifiable reward）、拒绝采样、蒸馏、合成数据、KL 正则与过度优化
- **对标**：CS336 A5（含 `test_grpo.py`、GSPO/MaxRL）；**rasbt《Reasoning from Scratch》ch3–ch8**（先建评测→推理时扩展→self-refinement→GRPO→改进 GRPO→蒸馏）；Nathan Lambert《RLHF Book》（免费在线，17 章）；HF LLM Course ch11–12；minimind `train_dpo/train_grpo.py`；nano-aha-moment（单文件单卡）
- **亲手实验**：同一基座上做 SFT / DPO / GRPO 三变体 → **同一评测口径**下对照 → 手写 GRPO 损失并逐项注释（advantage 从哪来、为什么要除标准差）→ 制造一次 reward hacking 并记录现象
- **判分证据**：`tests/test_grpo.py` 全绿 + 三方对照表（同基座/同评测/同种子策略）+ reward 曲线与失败样本分析
- **常见误解**：以为 DPO 不用 reward model 就"更简单"；以为 RL 一定比 SFT 强；把训练 reward 上升当成能力提升（不做 held-out 评测就是自欺）

## M7 · 评测：把"感觉变好了"变成"确实变好了"

- **核心问题**：benchmark 分数可信吗？污染怎么判断？为什么必须固定口径？评测方差有多大？
- **关键概念**：bpb / perplexity / CORE / 下游基准（GSM8K/MATH-500/MMLU/HumanEval）、pass@k、评测污染、few-shot 与 prompt 敏感性、方差与置信区间、LLM-as-judge 的偏置、可验证奖励 vs 学习型奖励
- **对标**：**rasbt《Reasoning from Scratch》ch3（先建评测再上技术，全书教学法基石）**；nanochat `core_eval.py`（单文件 CORE）；CS336 lecture 12；Berkeley Agentic AI MOOC "Agent Evaluation"；lm-evaluation-harness
- **亲手实验**：写一个"数学题判定器"（解析 + 数值比对 + 容错）→ 测它在 200 道题上的准确率与假阳性 → 给自己的两个模型跑同一套评测并给误差棒
- **判分证据**：判定器的单测 + 假阳性/假阴性样例分析 + 带误差棒的对照表（**不许只报均值**）
- **常见误解**：只看一个 benchmark 下结论；忽略 prompt 格式带来的巨大差异；把测试集当验证集反复调

## M8 · 智能体：工具、记忆、harness、长程任务

- **核心问题**：LLM 从"回答问题"到"完成任务"缺什么？harness 为什么比模型本身更能决定成败？self-judge 什么时候有效、什么时候是自欺？
- **关键概念**：工具调用/函数调用、ReAct 循环、context engineering（Karpathy/李宏毅都专讲）、记忆与压缩、harness 设计（沙箱、权限、反馈信号）、长程任务的误差累积、多智能体、self-judge / self-refine 的边界条件、可验证环境
- **对标**：李宏毅 GenAI-ML《Context Engineering》专讲；Berkeley LLM Agents MOOC + Agentic AI MOOC（含 "Post-Training Verifiable Agents"）；HF Agents Course（三大框架 + 排行榜）；rasbt《Reasoning from Scratch》ch5（self-refinement）；`PrimeIntellect-ai/verifiers`、terminal-bench、SWE-bench
- **亲手实验**：手写最小 ReAct 循环（不用框架）→ 给它 2 个工具（计算器 + 代码执行）→ 记录失败轨迹分类 → 加 self-judge 再跑，做消融
- **判分证据**：轨迹日志（成功/失败分类）+ self-judge 有无的成功率差 + "什么时候 self-judge 有害"的案例
- **常见误解**：以为 Agent 的瓶颈在模型智力（常在你的工具接口与反馈信号）；以为 self-judge 免费提升（它会放大原有错误）

## M9 · 前沿与安全（持续跟进区，不是一次性学完）

- **核心问题**：MoE/长上下文/多模态改变了什么？对齐与安全是"加一层"还是"改训练目标"？持续学习与"AI 训 AI"可行到什么程度？
- **关键概念**：MoE 稀疏激活、长上下文外推与记忆、多模态对齐、可解释性、红队与越狱、幻觉的成因、评测式安全保障、合成数据闭环、self-play、灾难性遗忘、模型合并
- **对标**：CS336 lecture 04（MoE）+ 论文精读清单；Berkeley Agentic AI MOOC（安全与红队）；`opendilab/awesome-RLVR`；`LeapLabTHU/limit-of-RLVR`
- **亲手实验（选题制）**：从"合成数据自训练一轮" / "拒绝采样提升数学" / "self-play 生成题目"三者中选一个，做最小闭环 + 反证
- **判分证据**：小实验 + 明确写出"这个方向的 no-go 是什么"（负结果不许擦除）
- **常见误解**：把"前沿"当成必须立刻掌握（正确姿势是保持索引能力 + 每季度更新一次本模块）
