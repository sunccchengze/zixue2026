## 三、成本估算（**标记为估算，必须在课题04 用实测替换**）

- 参考点（实测自 nanochat 公开文档）：**d12 ≈ GPT-1 量级 ≈ 0.1B**，在 8×H100 上约 **6 分钟**。
- T4 是 **SM75，无 bf16**（nanochat 自动退化 fp32，需手动 fp16 + GradScaler 才能提速）；
  等效算力约为 H100 的 1/15–1/25。
- **估算**：单 T4 约 12–20h，双 T4 DDP 约 **7–12h**（扩展效率按 60–80% 估）。
- **执行方式**：拆成两个 9h 会话（Kaggle 会话上限 9–12h），中间用 `/kaggle/working` 的 checkpoint 续训。
- ⚠️ 这个数字**不许照抄进报告**：课题04 结束后，用实测耗时替换，并在报告里写明"估算 vs 实测"的偏差。

## 五、硬纪律（出过事故的领域）

1. **实验卡制度**：上 GPU 前必须先写实验卡，经用户确认才开跑。模板：

   ```markdown
   ### 实验卡 #NN（课题NN / 模块 M?）
   - 假设（一句话，可被证伪）：
   - 命令（完整可复制）：
   - 预算上限：≤ ? GPU·小时（默认 3）
   - 停止条件：loss 不降 / 超过预算 / 出现 NaN → 立即停
   - 成功判据（跑之前先写死）：
   - 预期现象（**先写预测**，跑完对照——这是知行合一的咬合点）：
   - 产物归档：证据/run.yaml + 日志 + 曲线 + 哈希
   ```

2. **会话预检**（每次开 Kaggle 先跑）：`nvidia-smi` 看型号 →
   **T4 或 2×T4 才继续；P100 立即重开会话**（SM60，Triton 不可用，课题05 会在上面白烧配额）。
3. **断点续训是强制项**：Kaggle 会话随时可能断；每 N 步写 checkpoint 到 `/kaggle/working`（20GB 持久）。
4. **超时自停**：脚本内自带 wall-clock 上限（默认 3h），到点保存退出，不靠人盯。
5. **配额账本**：跑完立刻在 `memory/PROGRESS.md` 记：日期 / 平台 / GPU 型号 / 实际耗时 / 累计消耗 / 本周余量。
6. **不做无判据的实验**：没有"成功判据"就不许开跑——这是防止"烧配额摸鱼"的唯一有效办法。
