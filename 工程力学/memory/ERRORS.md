# ERRORS · 判例库（红线禁区）

> 记录用户在工程力学学习中反复出现的典型误区，转成"判例"，审稿/提问前必须先查这里，
> 同一个坑不能让用户第二次义正词严地掉进去而不被提前预警。

## 通用红线（导师自身纪律，继承自 probability/memory/ERRORS.md"通用红线"节，全学科通用）

- 绝不直接给定理证明——只给线索/反例/追问，不给答案。
- 报告必须有"我还存疑的地方"，缺这条视为不完整。
- **批量提问**：每条消息给 3~5 个编号问题，不零碎一问一答；仅当用户卡壳/答错时，
  临时退回"一次一问+提示阶梯"。
- 说"完全可能"之前先算σ（工程力学对应：先估算量级再下"肯定/不可能"结论）。
- 导师自己出错必须当场认领并写入本文件（示范作用）。


## 全学科通用判例（继承段 · 源自大学化学 2026-09-05 判例⑬–⑯，学科中性版）

> 细则见 `skills/科研式学习导师/SKILL.md` §5a"命题与判卷纪律"；原始判例全文在
> `大学化学/memory/ERRORS.md`。以下四条对**本学科同样具有约束力**：

- **通用判例⑬（题干不得含答案）**：出题/提问时，题干只给条件与待求，
  不得写进结论、公式名、示例形状——否则该题作废重出。
- **通用判例⑭（旁白不算错）**：用户的思考旁白、括号吐槽、手滑联想不构成答案；
  判卷只看其最终结论与论证。
- **通用判例⑮（字符级核对）**：指数、上下标、角标、正负号必须逐字符放大核对再判；
  看不准就明说"这一处我不确定"并定点确认，不许凭印象误判。
- **通用判例⑯（收口要有证据）**：禁止用少量基础题"检测/安慰"；掌握 = 当次对 +
  隔 1~3 天无提示再对 + 能讲清；课题/阶段收口的最低门槛为真题级综合卷（C 档）
  正确率 ≥70%，且同点错 ≥3 次升级为 leech 换角度重教。发现题目过易，主动自首重出。

## 工程力学特有红线（导师纪律）

- **先受力图，后方程**：静力学题用户若没画受力图就列方程，先打回补图，再判方程。
- **图要标数**：剪力图/弯矩图的关键值必须标出；禁止 ASCII 图（用户硬指令：生图模型生成 PNG）。

## 用户判例

- [2026-08-25] **力偶→单力（把等效力偶原理用成"力偶=单力"）**：A 计算 2(1) 用户说
  "把 E 点的力偶转换成在 B 点竖直向下的 F/2"，得 3F/2。两处错：①力偶**不能**换成单个力
  （R'=0、M≠0 → 纯力偶，无等效力；等效力偶原理只允许换**力偶对** F'·d'=M）；②重复记账：
  M 已在力矩方程里用过（解出 F_CD=F），又换成力进了一次力的方程。红线：力偶**只进力矩方程，
  永不进力的方程**（口诀"力偶只管转，无力争"）；再现时先问"力偶是几个力？换完几个力？
  平动账怎么办？"再用自相矛盾击破："在 B 的力对 B 矩为 0，原力偶对 B 矩却是 Fa"。
- [2026-08-24] **固定端与固定铰链混淆**：问固定端反力个数，用户答 2 个（Fx、Fy）并称
  "可以转动"——那是固定铰链。红线：固定端拒绝 2 平动 + 1 转动 = 3 个反力；用户再说固定端
  "能转"时，先问"若真能转，这根梁会长成什么样子？（绕墙摆动的摆杆）"再数运动。
  （2026-08-24 已恢复：用户自造"钉死在墙上"vs 铰链图像，重做区分对 2/3 个反力。）
- [2026-08-24] **力偶≠力矩，且 d 不随矩心变**：K4（力偶矩与矩心无关）用户标"我猜"答
  "d 不同所以 M 不同"。红线：d=两力作用线间距，只由两力本身决定；换矩心变的是两力各自
  力臂（一增一减同量，差值 d 不变）→ 力偶矩与矩心**无关**。再现时先让用户说"力偶是几个
  力、什么样"，再对比"单个力的矩 M_O(F) 带下标、跟矩心走"。
- [2026-08-22] **平衡条件缺"力矩"一半**：Q1 答"合力为零不够（可能是匀速直线运动）"——
  判断对、理由却是动力学论证；末尾说"自身不旋转"说明直觉在、词汇缺。红线：用户说
  "不转/不翻"时立刻接 ΣM=0，不让他悬在"不知道怎么描述"上。
- [2026-08-22] **"约束反力"≠牛顿第三定律"反作用力"**：问反力方向时用户按作用-反作用
  （"绳拉物体，物体反过来拉绳"）解释。红线：受力图只画**作用在研究对象上**的力；
  用户一旦开始描述"物体给约束的力"，立刻提醒"那是作用在约束上的力，不画"。
- [2026-08-22] **二力杆误读为杠杆原理**：用户用跷跷板力矩平衡（G1·L1=G2·L2）回答二力杆。
  红线：跷跷板有支点=3 个力，属力矩平衡问题；二力杆是只受两个力的物体，二力必共线。
  再现时先让用户数"这个物体上到底受几个力"。

## 【排版判例】作业单类 docx（2026-09-18）

- **Word 合并相邻同边框段落**：用 N 个"带下边框的空段落"画手写横线，Word 把它们当成一个边框组，
  只画组的底边 → 5 条线塌成 1 条。**红线：手写横线一律用表格行边框（insideH + bottom）实现。**
- **带边框段落的高度 ≠ 字号×行距**：边框与行高会额外撑开，估算单页时按"实际量"算，别用估算值。
- **图片段落的高度由 `wp:extent`（EMU）决定**，不是字体行高；插图行要写 exact 行距 = 图高。
- **验证套路**（沙箱无 LibreOffice，apt 源不可达）：① 生成时算一遍高度；② `docx_page_audit.py`
  读回 XML 再算一遍（两个独立实现互校）；③ `docx_preview_pdf.py` 画出 PDF 一眼看页数与版式。
  三关都过才算"真的能一页打完"。

## 【运维判例】快照会损坏仓库里的二进制文件（2026-09-18 发现）

- **现象**：新会话开工时 `git status` 显示 21 份 typst PDF"已修改"，体积变大（如课题01：560 KB vs 352 KB）、
  用 PyMuPDF 打开报 `zlib error: incorrect header check`、**文本层抽不出一个字**。git 里（origin/main）的版本
  完全正常（352 KB / 7 页 / 7917 字）。
- **判断**：这不是排版问题，是**工作区文件在快照搬运中被破坏**（二进制流损坏）。同理可能波及 docx/图片/压缩包。
- **处置**：`git checkout HEAD -- <文件>` 用 git 里的版本覆盖，校验能打开、页数/字数正常后再继续。
- **纪律**（三条）：
  1. 新会话开工先 `git fetch origin && git reset --hard origin/main`（远端是真相源，见各学科 HANDOFF 运维判例）；
  2. **提交前对二进制产物做可读性抽检**（PDF 抽文本、docx 用 python-docx 打开、图片用 PyMuPDF 打开），
     不能只看文件存在与体积；
  3. 发现"工作区比 git 里大且打不开"→ 一律从 git 恢复，不要试图修复文件本身。

## 【作图判例】解答图必须"先自检后作图"（2026-09-18）

- 用户要求"调用生图模型"，但**力学解答图不能交给生图模型**：角度（40°/10°/45°）、比例（30:40:50）、
  力臂（150/200 mm）都是定量量，生图模型只能画"像"，中文标注还常出乱码。
  **红线：此类图一律用代码精确绘制**（`matplotlib` + 解析几何），并向用户说明缘由。
- 正确流程固化为三步：① 跑数值自检（结果必须与教材答案逐位吻合，不通过就抛异常、不许出图）；
  ② 用自检通过的那组数作图（图上每个数字都来自自检）；③ **逐张肉眼复核**（本轮到第三版才干净）。
- 已知踩坑：Matplotlib 的 `_{1}`、`\sin` 等 mathtext **不认中文/下标字符 ₁₂₃**（会变豆腐块）——
  中文单位与文字用普通字符串，数学符号才走 `$...$`；标注重叠用"手工摆位 + 白底 bbox"解决，
  别指望自动避让。
