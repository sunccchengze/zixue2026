# 概率论作业包制作工作流

目标：用户只需给出概率论作业列表，自动完成“定位原题 → 规范试卷 → 完整解析 → 多路校验 → PDF验收”。面向用户的成品保持**简约、高效、可打印、可手写、经得住逐题检查**；复杂校验仅作为内部质控，不额外交付，除非用户明确要求。

## 一、触发与默认行为

以下任一输入自动触发本技能，不先问“要不要开始”：

- 群公告、学习平台作业截图；
- “第X章奇数题”“A、B两部分”等题号列表；
- 教材习题页或教材PDF；
- 要求制作概率论作业试卷、答案或解析。

先读取仓库根 `AGENTS.md`、`probability/memory/HANDOFF.md`、本技能和 `reference/acceptance-checklist.md`。若仓库已有教材，先全面定位；不要让用户重复上传已有材料。

仅当题目原文在仓库、附件、公开合法来源中均无法取得，或版本存在实质冲突时，才定点请求缺失页面。不得凭印象编题。

## 二、默认交付物

### 1. 试卷 PDF

- A4，白底黑字，正式试卷风格；
- 标题使用用户指定文本；未指定时用“日期 + 概率论作业”；
- 自动填写：孙承泽 / 2253710052 / 能动强基2501；
- 只收入指定题目，题号保留教材编号；
- 严格遵守指定页数；未指定时按可书写性合理分页；
- 按证明题、计算题、短答题的实际书写量分配空间；
- 默认重排文字与公式，不粘贴教材扫描页、水印、二维码或背景；
- 必需图形优先矢量重绘；只有无法可靠重绘且用户允许时才裁取原图。

### 2. 完整解析 PDF

- 与试卷逐题对应；
- 最简方法优先，但不得省略决定正确性的步骤；
- 先交代概念，再使用概念；证明题不得用“同理”“由归纳假设”跳过核心展开；
- 明确样本空间、分母、计数对象、补事件、边界条件及最终答案；
- 数值答案保留精确形式，必要时附小数核对；
- 解析可比试卷多页，不为压缩页数牺牲教学完整性。

### 3. 题目质量分析

用户明确要求时才作为独立成品交付。包括知识覆盖、难度、梯度、易错点、预计用时和训练价值。内部校验日志、脚本输出不作为用户成品。

## 三、原题定位与誊录

1. 确认书名、版次、章节、习题编号和页码。
2. 将作业通知中的范围转换为明确题号集合；“奇数题”必须程序化生成并与首末题核对。
3. 放大原页逐字符核对：
   - 补集横线覆盖范围；
   - 上下标、角标和指数；
   - `∩`、`∪`、差集、条件概率竖线；
   - 分式、组合数和括号层级；
   - “至少/至多/恰有/仅有”；
   - 抽取是否放回、停止规则；
   - 跨页续题、图表和公共题干。
4. 建立内部对应表：教材页码 → 原题号 → 试卷题号 → 解析题号。
5. 对扫描模糊处至少做两次独立读取；无法确定时不得静默猜测。

## 四、解题与教学写法

### 方法优先级

优先选择最短且最自然的方法：直接计数、补事件、分类计数、容斥、古典/几何概型、超几何分布、全概率、贝叶斯、独立性定义。直接法和补集法都简单时，选更符合题意的一种，另一种用于内部验算。

### 必须解释的节点

- 为什么总样本数这样取；
- 为什么没有重复或遗漏；
- 为什么某事件恰是另一个事件的补；
- 几何区域的边界为何是三角形/梯形，面积如何得到；
- 条件概率的条件是什么；
- 独立与互斥的区别；
- 归纳法的基础、假设、递推和收口。

### 证明题模板

1. 用一句话说明定理/概念；
2. 给最小例子帮助理解；
3. 写明待证结论；
4. 完成关键展开；
5. 解释各类项如何对应；
6. 明确“证毕”。

禁止把教学责任转嫁成“剩下自行展开”。

## 五、每题双轨质控

每题至少采用一种主解法和一种独立校验路径。按题型选择：

- 事件运算：真值表或基本原子；
- 有限样本空间：穷举脚本；
- 组合计数：另一种分类、生成函数或动态规划；
- 几何概型：直接区域与补集面积互证；
- 条件概率：联合概率表与公式互证；
- 独立性：代数证明与基本原子枚举；
- 证明题：小规模有限集合/数值实例检验，再人工检查一般证明；
- 数值结果：精确分数计算并约分，必要时做小数数量级检查。

程序通过不等于证明正确。脚本只验证可验证的部分；最终仍须回读题意、假设和论证。

发现争议时：回到原题 → 独立重算 → 定位分歧 → 修正源文件 → 全量重建 → 全量复验。若原答案正确，也要把过度跳步的说明补全。

## 六、数学排版规范

- 交、并显式写为 `∩`、`∪`，不依赖相邻字母暗示交集；
- 补集优先排为上标 `c`，避免扫描横线和组合附加字符错位；
- 下标、上标使用 PDF 引擎原生标签/公式，不使用字体不支持的 Unicode 组合字符；
- 括号必须覆盖正确范围；复杂补集使用方括号；
- 字体可能缺失的空集、全集符号，必要时写“空集”“全集”；
- 不使用源码式、难读的 LaTeX 字符串充当最终排版；
- 公式较长时分行，不让自动换行破坏结构。

## 七、PDF 构建与成品验收

先生成可重复构建的源文件/脚本，再生成 PDF。每次修改都从源重新构建，不直接手改二进制 PDF。

必须完成：

1. 程序检查页数，试卷严格等于指定页数；
2. 检查无空白页、截断、越界、孤立题号；
3. PDF文本提取检查题号、关键公式和答案是否存在；
4. 将每页渲染为图片，肉眼查看标题、上下标、补集、分页和答题线；
5. 对风险页放大检查，尤其是原题中有横线、指数、复杂括号的题；
6. 运行全部内部校验脚本；
7. 确认试卷、解析使用同一版题面；
8. 用哈希或修改时间确认呈现的是新文件，避免查看器缓存旧PDF；必要时关闭后重新打开。

详细门禁见 `reference/acceptance-checklist.md`。任一硬门禁失败，不得声称“已完成”。

## 八、文件与版本管理

- 当前作业沿用清晰的日期目录和稳定文件名；旧版本不得与修订版无标识并存；
- 构建脚本、内部审计脚本与成品放同一作业目录；
- 只向用户打开主交付物；内部审计文件不主动展示；
- 更新 `probability/memory/PROGRESS.md` 与 `HANDOFF.md`；
- 按仓库纪律提交并推送当前会话分支。

## 九、失败模式清单

出现以下任一项必须停止交付并修复：

- 仅凭截图通知猜教材题目；
- 补集横线、上下标未经放大核对；
- 人工罗列停止序列却没有状态树/穷举复核；
- 将大正方体切块题误读成每个小块分别涂色；
- 几何概型把边界半三角形算成整矩形；
- “至少两个同类”的补事件未说明；
- 未解释容斥原理就直接要求读者接受归纳展开；
- 源码正确但 PDF 字体缺字、出现大空格；
- 修改解析后没有重新生成 PDF；
- 把内部校验报告当作用户需要的主要成品。
