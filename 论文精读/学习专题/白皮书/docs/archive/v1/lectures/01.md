#### 1. 生活与物理直觉引子：五种人围着一张桌子转

想象一个必须闭环的评图现场：

- **甲方**（优化器）：只说"再往这个方向改一点"，自己不会画图也不会算；
- **建筑师**（几何参数化）：把"改一点"翻译成新的控制点坐标；
- **结构助理**（网格变形）：建筑一改，他手上那张有限元网格必须跟着挪；
- **评审专家**（CFD 求解器）：坐下去算几小时，给一个分数；
- **速记员**（伴随求解器）：同一晚顺手把"每个参数各影响多少分"全抄下来。

这五个角色之间**传递了什么**、**谁等谁**，就是 XDSM 要画的东西。
它的用处不是好看，是让你一眼看出：**哪一格最贵、哪一格在串行浪费所有人的时间。**

> **一句话记住**：XDSM 是"谁把什么交给谁"的账本；对角线上是**干活的模块**，非对角线是**模块之间传的数据**。

#### 2. 工程死穴：把"慢"精确定位到哪一格

论文用开源框架 **MACH-Aero** 作为 CFD-based ASO 的代表，并把整个流程用 XDSM 画出来
〔原文 P5 "The workﬂow for the MACH-Aero framework"〕。对照 Fig. 1，本讲把流程拆成可操作的五步（术语首次出现，当场拆开）：

**先认词**（本讲所有新词都在此定义，后面不再解释）

| 中文 | 英文 | 一句操作定义 |
| :--- | :--- | :--- |
| 设计变量 | design variables | 你能改、优化器也能改的那组数（如 FFD 控制点坐标）。它是"输入向量 x" |
| 目标函数 | objective function | 要最小化的那个标量（论文惯例：把最大化升阻比写成最小化 −L/D） |
| 气动外形参数化 | geometric parameterization | 把"形状"编码成"有限个数"的映射；正向：数 → 外形 |
| FFD | Free-Form Deformation，自由变形：Free 自由、Form 外形、Deformation 变形 | 在物体外套一层弹性控制网格，挪控制点，物体跟着光滑变形；控制点数＝设计变量数 |
| 网格变形 | mesh deformation | 外形改了，CFD 那张体网格必须跟着改；MACH-Aero 用反距离法 IDWarp |
| 伴随求解器 | adjoint solver | 一次回代算出目标函数对**全部**设计变量的偏导（讲 02 详讲机制） |
| XDSM | eXtended Design Structure Matrix，扩展设计结构矩阵 | 方格表：对角线＝模块，非对角线＝数据，箭头＝执行顺序 |
| SLSQP / SNOPT | 两种梯度优化算法 | Sequential Least Squares Programming / SQNonlinear Programming，都是"给梯度和边界、返回下一组 x"的黑盒 |

**流程实况**（逐句贴原文）：

1. **预处理**：为基准外形建立 CFD 网格与初始几何参数化（例如 FFD 控制盒）
   〔原文 P5 "the CFD mesh and the initial geometric parameterization"〕；
2. **定问题**：通过 Python 接口在优化器里定义目标函数、约束与设计变量上下界
   〔原文 P4 "objective function, constraints"〕；
3. **每轮迭代**：优化器决定怎么更新设计变量 → 外形变形 → 评估几何约束及其导数 → 体网格变形 → 跑 CFD → 伴随求解器算气动导数
   〔原文 P5 "the gradient-based optimizer determines how to update the design variables"〕；
4. **闭环**：优化器用目标值与梯度定搜索方向与步长，得到下一轮的 x；
5. **模块化封装**：MACH-Aero 里所有部件都用 Python 接口包起来（pyGeo 做 FFD/OpenVSP、IDWarp 变网格、ADflow/DAFoam 求解并带伴随）
   〔原文 P6 "all the components are wrapped using a Python interface"〕。

论文还点名：**SU2 是同一套流程的另一个实现**——SU2 GEO 做 FFD 参数化并评估几何约束（值与导数）、SU2 CFD 跑正向与伴随、SU2 DOT 求气动导数、SU2 DEF 在 x 更新后变形网格，默认优化器是 SciPy 的 SLSQP
〔原文 P6 "SU2 CFD performs both direct and adjoint computations"〕。
**这就是你每天都在敲的那四个命令**，只是原文把它的学术位置说清楚了。

> **配图位置**：XDSM 的模块-数据关系图已放在第零章 0.2 末尾（`images/L01_s2_xdsm_matrix_zh.png`），
> 此处不重复贴图；读图方法见本讲 §5。论文实物是 Fig. 1（PDF p5），建议你**先自己画一遍再去看原图**。

> **本讲第一记暴击**：整个循环里，**唯一"只输几个数、却吞掉全部时间"的环节是 CFD 那一格**。
> 后面十讲无论多花哨，本质上都在做两件事之一：**少进这一格**（代理模型/降维）或**让这一格便宜**（算子/加速）。

#### 3. 数学从 0 到 1：为什么"必须梯度"，以及梯度为什么买得起

**第一步：数一数无梯度法要付多少钱。**
第零章 0.3 已给出论文的定性论断（二次到立方增长 vs 近线性）〔原文 P3 "quadratic or even cubic growth of function evaluations"〕。
现在把它算成一个数：设"要评估的次数 ≈ c^n"（c 为常数、n 为设计变量个数），

- n = 8，c = 5 → 5^8 = **390,625** 次 CFD；按 2 小时一次 = 89 年。
- n = 20，c = 5 → 5^20 ≈ **9.5 × 10^13** 次。宇宙年龄约 4.3 × 10^17 秒，也不够你花。

这不是吓你，这解释了为什么遗传算法/粒子群在真实叶栅上永远只能玩"小维数玩具题"。

**第二步：梯度法要什么。** 它要 ∇f = (∂f/∂x_1, …, ∂f/∂x_n)。
最笨的求法是中心差分：每个变量扰动两次 → **2n 次 CFD**。n = 100 就是 200 次 CFD 换一个梯度方向——**比无梯度还慢**。

**第三步：伴随把 2n 次砍成 1 次。**
一句话机理（严格版在讲 02 与 P02 那篇伴随综述）：CFD 求解器内部是"一串复合映射"（网格 → 残差 → 系数 → 目标）。
若从**输入端**往回推，每换一组输入扰动就要重跑一遍；
若从**输出端**把链式法则反过来算一次，则**同时**得到它对每个输入的偏导——这正是深度学习的反向传播干的同一件事。
论文原话：**伴随方法以与设计变量个数无关的成本精确计算气动导数**
〔原文 P3 "at a cost independent of the number of design variables"〕，
并且其 Jacobian-free 实现靠的是**源代码变换的自动微分**〔原文 P5 "Jacobian-free implementation using source code transformation algorithmic diﬀerentiation"〕。

![正向 vs 反向：一次回传拿到全部偏导（手绘笔记版）](./images/L02_s3_adjoint_one_backpass_zh.png)

**第四步：既然梯度这么强，为什么还要机器学习？**（这是 B4 那个问题的正解）
因为**梯度便宜 ≠ 整条链便宜**：每一步迭代仍要一次真实 CFD（几小时），
而多目标、鲁棒、设计点外约束、几何合法性这些事会把"迭代步数"乘上十到百倍。
论文 §1 的结论是：即便有伴随，ASO 仍满足不了"快速交互式优化设计"这类实际需求〔原文 P3 "iterative and costly simulation-based evaluations"〕。
**ML 的位置就是：把"每步一次的 CFD"换成"每步一次的神经网络"，代价是精度、外推风险与训练成本——这三笔账后面各讲逐一摊开。**

#### 4. 论文 §2.2 的六个挑战：一条一条背下来

作者把困难写成**两个复合挑战**：气动分析的高计算成本 + 几何设计空间的高维性
〔原文 P5 "two compounding challenges in ASO"〕，然后在 §2.2 展开成六条（**编号按原文顺序**，"First/Second/…/Lastly"）：

![六个挑战，其实是三句话：形状太啰嗦、算得太贵、优化太笨（手绘手账版）](./images/L01_s5_six_challenges_zh.png)

| # | 挑战（原文口径） | 机理：为什么致命 | 你的平台里对应哪一处 |
| :---: | :--- | :--- | :--- |
| ① | **参数化低效**：高维设计空间里有大量**畸形形状**区域 | 变量一多，空间里就出现波浪面之类异常外形；CFD 对它们"耗时甚至无法收敛"，可能直接导致优化失败〔原文 P6 "abnormal shapes, such as wavy airfoil surfaces"〕 | NSGA-II 在 74 维里随机采样 → 大量畸形叶型 → SU2 不收敛（你的 E3 日志就是这个） |
| ② | **多目标 CFD 优化太贵** | 没有高效算法求解高维多目标；常用替代是"化成一串单目标逐个解"，只找到 Pareto 前沿上**寥寥几个点**且不保证分布均匀〔原文 P6 "only a few points in the Pareto frontier"〕 | 你的 100 × 200 代是在**代理模型**上跑的；换成真 CFD，直接不可行 |
| ③ | **确定性优化忽略了不确定性** | 工况波动、磨损与制造误差是随机的；忽略它会造成实际性能意外损失。补救办法（加设计点 / 用随机指标）又**大幅增加成本**〔原文 P7 "Ignoring these uncertainties may in practice lead to unexpected performance loss"〕 | MC Dropout 的 UQ 就是在补这一格——你的覆盖率 η 65% 是这一格**有多难**的实测证据 |
| ④ | **缺把不同数据与模型一起用起来的技術** | Euler / RANS / 粗网格 / 实验数据都在手边，"理想情况下应当用实验数据补充多保真数值模拟来指导优化"，但没有成熟融合手段〔原文 P7 "lack of techniques to utilize"〕 | 140k 粗网格 vs 3.55M 细网格：你有两档保真度，**却没有任何融合模型**（这就是 Co-Kriging 的位置，讲 02） |
| ⑤ | **不连续问题**梯度法啃不动 | 低雷诺数下转捩主导，模型里存在**没有连续导数的函数**，给伴随实现带来困难；高维进一步放大；不连续目标函数本身就不适合梯度法〔原文 P7 "there are discontinuous ASO problems"〕 | 激波出现时的 η 突降（你的 0.9211 → 0.872，**E3 定性证据**）是同一族问题：目标面有拐点 |
| ⑥ | **交互式优化**要求近实时 | 高保真仿真成本使"交互回合"太慢，谈不上 interactive〔原文 P7 "interactive design optimization where aerodynamic evaluations run near instantaneously"〕 | 你的 ONNX 0.13 ms / API 1.85 ms 与 WASM 前端，**恰好就是这条挑战的工程答案**（口径：E2） |

> **读法提示（本讲的方法论）**：作者列挑战的顺序不是随机的——
> ①③⑤是"设计空间本身"的病，②④⑥是"评估与循环"的病。
> 记住这个"3 + 3"的分组，比背六条有用得多。

#### 5. 数据与图表：怎么读 Fig. 1（你的审美挑剔在这里最有用）

**怎么读它**：先只看对角线（五个模块），问"哪一格在等人"；再看灰粗线（数据流），问"哪份数据被反复搬运"；最后看黑色细线（执行顺序），问"有没有可以并行却被串起来的两格"。

**可以挑剔的地方**（我们的判断，不是论文说的）：① 图上没有标"成本"，读者无法一眼看出瓶颈量级，若加一列"每次调用耗时"教学价值立刻翻倍；② 没有画出"几何合法性/过滤"这一格，而它正是 §4.1.2 的重头戏——流程图为"标准流程"服务，为"改进点"留白。

#### 6. 审稿人批判（本讲可攻击的点，含对论文本身的）

1. **§2 的"两个复合挑战"与"六个挑战"关系没量化**：文中给了 ①–⑥ 的定性描述，却没给"各挑战在典型问题上损失多少百分比"的量表；
2. **以 MACH-Aero 为例有代表性偏差**：论文自己说"总体流程与其他 CFD-based ASO 框架相似"，但 SU2 / 自研平台的**网格自适应**与**并行策略**差异会显著改变瓶颈位置；
3. **⑥"交互式"在 2022 年的口径与今天不同**：当时把 ANN 推理当"近实时"（毫秒级），今天还要考虑前端部署、精度保证与失效兜底；
4. **③与④其实可以合并成"多源信息利用"**：把它们拆开列，容易让初学者误以为是两件独立的事。

#### 8. 你的项目接哪一步（六层阶梯的"回收"层）

| 本讲概念 | 你代码里对应的动作 |
| :--- | :--- |
