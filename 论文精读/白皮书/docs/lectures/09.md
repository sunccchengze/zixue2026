#### 3. 场景引子：四位医生同一天出诊

- **代理式（surrogate-based）**：第一位医生先自己攒一本病历手册，**每次真检查都在补手册**[^L09-1]；
- **交互式（interactive）**：第二位医生的手册已经厚到不用查了，**在线不再碰 CFD**，当场秒答；
- **RL 优化**：第三位是**会看片子的住院医**，一眼就知道往哪儿切；代价是**培养他花了五年**；
- **生成式反设计**：第四位按你的描述直接画一个心脏——**快，但它不知道你要的是最优**[^L09-4]。

**四格对照**（每格下方写它治的是哪个瓶颈；右上角短横是落地难度，越短越容易开工）：

#### 4. 工程死穴 + 先认词：架构决定"你能不能收工"

**先认词 · 第一批**

| 中文 | 英文 | 一句操作定义 |
| :--- | :--- | :--- |
| 加点准则 | infill criterion / acquisition | 决定下一个 CFD 点算在哪的打分函数；常见是最大化 EI 或**最小化置信下界 LCB**[^L09-8] |
| 序贯优化 | sequential / iterative refinement | 训代理 → 选点 → 跑 CFD → 并入样本 → 重训，循环 |
| EGO | Efficient Global Optimization | 用 Kriging 的 μ+σ 做 EI 的序贯优化（讲 02） |

**先认词 · 第二批**

| 中文 | 英文 | 一句操作定义 |
| :--- | :--- | :--- |
| SEGOMOE | Super-Efficient GO + Mixture Of Experts | 把 Superego[^L09-6] + Kriging-with-PLS + ME 拼起来处理较大规模问题 |
| 弱/强学习者 | weak / strong learner | ActivO 的思路：弱学习者找"值得探的区域"[^L09-10]，强学习者在里面定最优点 |
| 泛化性 | generalizability | 在训练工况（M、Re）之外的表现；RL 用**物理特征**当状态可提升它[^L09-3] |

**死穴一（Table 4，p60，一条能背出来的规律）**：把该表的"设计变量数"排序：
2 → 4 → 5 → 6 → 8 → 8 → 8 → 10 → 12 → 17 → **30（ANN）** → 40 → 42 → 48 → 19/75 → 80 → 36/72/108。

**分界线清清楚楚：≤17 维的清一色是 Kriging 或 Manifold mapping；一旦到 30 维，代理模型换成 ANN；
到 72–108 维，连 ANN 都吃力，只剩"高维翼型 + C_p 匹配"这类专门设计。**

论文自己的结论是：**代理式优化不随维度良好扩展，因而不适用于高维设计问题**[^L09-7]。

![维度切换速查卡：17 维及以下用 Kriging / 流形映射，30 维起换 ANN](./images/L09v2_s3_dim_switch_zh.png)

这条规律还有一个更狠的实测：CRM 机翼在 192 个 FFD 设计变量[^L09-21]上直接做代理式优化。

结果**跑了一千次 CFD 也没能改进基准机翼**[^L09-18]。

换成从深度学习最优样本里用 PCA 抽出 40 个全局机翼模态[^L09-19]，
才做到与 192 变量的 CFD 优化几乎同样有效。

后者的总成本约 500 次 CFD 评估[^L09-20]（伴随按 0.5 次折算）。

**第二条死穴**：加点准则会被**不准确的代理模型**反噬——
它们常把新样本加到畸形外形上，而这些外形对改进毫无贡献[^L09-9]。
所以合法性过滤（讲 06）不是锦上添花，是序贯优化的**必备闸门**。

> 🧭 **呼吸点**：§4 的账——维度决定代理选型，代理精度决定加点质量，
> 加点质量决定你能不能收工；三件事是同一条链。

#### 5. 数学从 0 到 1：四种架构的目标函数长什么样

**（a）代理式（序贯）**

外层：`max_x EI(x) s.t. S_valid(x) ≥ s_min，x ∈ [lb, ub]`（EI 定义见讲 02 §3(e)）。

**一个完整的数字算例**（照讲 02 的手算延续）。

候选点 A（μ=0.90, σ=0.10）、B（μ=1.10, σ=0.60），ξ=1.00。

算得 EI_A = 0.108、EI_B = 0.185 ⇒ 选 B。

**但若 B 的合法性 S_valid = 0.42 < 0.7 ⇒ B 被过滤掉，退而选 A。**

这一步就是"过滤改变优化轨迹"的最小可复现例子（`code/kriging.py` 可跑通 EI 计算）。

![只看收益选 B；加上合法性闸门后 B 被划掉，改选 A](./images/L09v2_s2_ei_filter_zh.png)

**（b）交互式**

在线：`min_x ŷ_ANN(x) s.t. 几何/工艺约束`；**没有 CFD、没有重训**。

可交互的门槛是"响应时间 < 人的注意力间隔"（工程上取 100 ms 级）。

论文给出的可比数字：Secco & de Mattos 的 ANN 模型（10^5 样本、40 输入）。

它实现了相对全位势代码 **4,000×** 加速[^L09-11]。

**这是论文口径的加速比，你对外写 100,000× 时，必须说明分子分母各是什么**（见讲 07 §10）。

![钱从循环里挪进了训练里：这就是交互式的全部秘密](./images/L09v2_s3_interactive_cost_zh.png)

🔮 **下注**：你的平台最像四位医生里的哪一位？先把答案写下来，再看下一行。

👊 **打脸**：你多半会说"第二位（当场秒答）"——但你的病历本只有一半厚。

论文自认**代理式优化不随维度良好扩展**[^L09-7]。

RL 优化器也**不随设计变量数良好扩展**[^L09-24]。

甚至明说：不用低保真或代理模型打底，训练 RL 优化器相比常规优化器**没有任何优势**[^L09-25]。

第二位医生能秒答，是因为他背后有 10⁵ 本病历。
你有一千组样本，却想用同样的口气说话。

**（c）RL 优化**

学策略 π_φ(a|s)：`max_φ E[Σ γ^t r_t]`；**不需要气动力学导数**。
论文的评语很克制：一个训练充分的 RL 优化器**据报告能达到梯度法级别的效率而不使用导数**[^L09-2]，但训练过程可能耗时。

关键实验事实（Fig. 47）：**大部分减阻在头 5 步内完成**[^L09-13]。

而且只在 M=0.76、Re=5×10⁶ 训练的策略，
可在 M∈[0.72,0.76]、Re∈[5×10⁶,1×10⁷] 上照常减阻[^L09-14]。

**读法**：头 5 步吃掉绝大部分收益 ⇒ RL 的"快"来自**动作先验**（它从不往畸形方向动），不是来自算法天赋。

![头五步吃完大部分减阻：快来自动作先验，不是算法天赋](./images/L09v2_s4_rl_five_steps_zh.png)

**（d）合法性门控的统一写法（本白皮书构造，非原文）**

四种架构都能写成同一句"在线目标 = 收益 − 风险"：

```
J(x) = [−ŷ(x) 或 EI(x) 或 E_π[Σγ^t r_t] 或 −‖G(z)−x_target‖²]
       − β₁(1−S_valid(x)) − β₂·1[d(x, X_train) > d_max]
```

三项惩罚分别对应**合法性**与**外推距离**；β 由你对"愿不愿意让优化器冒险"来定。

![统一门控式：收益 − 合法性惩罚 − 外推惩罚，三项分别来自模型、统计量与你](./images/L09v2_s3_gate_formula_zh.png)

**（e）生成式反设计**

给定目标性能 y*，学后验 P(x|y)：conditional GAN / conditional VAE。
论文明确两点：

1. 反问题在 ASO 里**大多是病态的**——不同形状可以有同样性能[^L09-15]；
2. 因此它更适于**低保真概念设计**，而不是交付级最优点[^L09-4]。

工业侧同页还点名 Monolith AI 与 Altair 把 AI 生成式设计当门面，案例包括**叶轮机械叶片**[^L09-16]。

![同一个目标性能，能画出无激波、弱激波、强激波三种外形](./images/L09v2_s5_illposed_zh.png)

> 🧭 **呼吸点**：§5 的账——四种架构的目标函数长得不同，
> 但都能塞进同一句"收益 − 风险"，区别只是风险那两项谁来出。

#### 8. 审稿人批判（本讲可攻击的点，含对论文本身的）

1. **Table 4 只给"设计变量数/代理类型/目标"，不给 CFD 次数与最终收益**：于是"17 维 Kriging"与"108 维 Kriging"看起来一样可行，
   而真实差别（收敛是否失败、多少样本）全被抹平——**这是综述表格的通病，本讲 §2 已经替你补了一条分界线**；
2. **"交互式"没有一句成本核算**：10^5 样本的 RANS 训练要多少核时？论文只报推理精度不报训练账，
   这正是 Abstract 里承认的"ML 训练成本高"〔原文 P1 "practical large-scale design optimizations remain"〕在正文里被淡化的地方；
3. **RL 一节只给成功案例**（超临界翼型 3 个 Hicks–Henne 变量），没有任何失败案例或"多少维就崩"的边界；
4. **生成式反设计与优化被并列在"优化架构"里，但它们解决的问题不同**：一个是"给性能求形状"，一个是"给约束求最优形状"；
   并列会误导读者以为生成式设计可以做最优化。
5. **顺带批本白皮书自己**：§5(d) 那个统一门控式是**我们构造的**，不是论文里的式子。
   它好记，但你拿去组会时得说清"这是组织框架，不是被引方法"。
