#### 1. 生活与物理直觉引子：四种看病策略

- **代理式（surrogate-based）**：先自己攒一本"病历手册"（代理模型），按手册判断"下一步该查哪项"（加点准则），
  只在最可疑处开一次真检查（CFD）——**每次真检查都在补手册**〔原文 P59 "rely on an iterative model reﬁnement"〕；
- **交互式（interactive）**：手册已经厚到不用查了，医生当场翻，秒级给结论（**在线不再碰 CFD**）；
- **RL 优化**：培养一个**会看片子的住院医**，他一眼就知道往哪儿切；代价是**培养他花了五年**（训练成本）；
- **生成式反设计**：直接对病人说"我要一个健康的心脏"，让生成器画一个出来——**快，但它不知道你要的是最优**〔原文 P59 "could be distinct from the true optimum"〕。

#### 2. 工程死穴：架构决定"你能不能收工"

**先认词**

| 中文 | 英文 | 一句操作定义 |
| :--- | :--- | :--- |
| 加点准则 | inﬁll criterion / acquisition | 决定下一个 CFD 点算在哪的打分函数；常见是最大化 EI 或最小化置信下界 LCB〔原文 P60 "minimizing the lower conﬁdence bounding"〕 |
| 序贯优化 | sequential / iterative reﬁnement | 训代理 → 选点 → 跑 CFD → 并入样本 → 重训，循环 |
| EGO | Efficient Global Optimization | 用 Kriging 的 μ+σ 做 EI 的序贯优化（讲 02） |
| SEGOMOE | Super-Efficient GO + Mixture Of Experts | 把 Superego + Kriging-with-PLS + ME 拼起来处理较大规模问题〔原文 P59 "superego"〕 |
| 弱/强学习者 | weak / strong learner | ActivO 的思路：弱学习者找"值得探的区域"，强学习者在里面定最优点〔原文 P61 "weak"〕 |
| 泛化性 | generalizability | 在训练工况（M、Re）之外的表现；RL 用**物理特征**当状态可提升它〔原文 P59 "using physical features rather than geometric parameters as the state"〕 |

**死穴（Table 4，p60，一条能背出来的规律）**：把该表的"设计变量数"排序：
2 → 4 → 5 → 6 → 8 → 8 → 8 → 10 → 12 → 17 → **30（ANN）** → 40 → 42 → 48 → 19/75 → 80 → 36/72/108。
**分界线清清楚楚：≤17 维的清一色是 Kriging 或流形映射；一旦到 30 维，代理模型换成 ANN；到 72–108 维，连 ANN 都吃力，只剩"高维翼型 + C_p 匹配"这类专门设计。**
论文自己的结论是：**代理式优化不随维度良好扩展，因而不适用于高维设计问题**〔原文 P60 "does not scale well with the dimensionality"〕。

**第二条死穴**：加点准则会被**不准确的代理模型**反噬——它们常把新样本加到畸形外形上，而这些外形对改进毫无贡献〔原文 P61 "these criteria always suﬀer from inaccurate surrogate models"〕。
→ 所以合法性过滤（讲 06）不是锦上添花，是序贯优化的**必备闸门**。

#### 3. 数学从 0 到 1：四种架构的目标函数长什么样

**（a）代理式（序贯）**
外层：max_x EI(x) s.t. S_valid(x) ≥ s_min，x ∈ [lb, ub]（EI 定义见讲 02 §3(e)）。
**一个完整的数字算例**（照讲 02 的手算延续）：候选点 A（μ=0.90, σ=0.10）、B（μ=1.10, σ=0.60），ξ=1.00 → EI_A=0.108、EI_B=0.185 ⇒ 选 B；
**但若 B 的合法性 S_valid=0.42 < 0.7 ⇒ B 被过滤掉，退而选 A**。这一步就是"过滤改变优化轨迹"的最小可复现例子（`code/kriging.py` 里可跑通 EI 计算，过滤惩罚按 §(d) 加）。

**（b）交互式**
在线：min_x ŷ_ANN(x) s.t. 几何/工艺约束；**没有 CFD、没有重训**。
可交互的门槛是"响应时间 < 人的注意力间隔"（工程上取 100 ms 级）。
论文给出的可比数字：Secco & de Mattos 的 ANN 模型（10^5 样本、40 输入）实现了相对全位势代码 **4,000×** 加速〔原文 P61 "4,000"〕——
**这是论文口径的加速比，你对外写 100,000× 时，必须说明分子分母各是什么**（见讲 07 §8）。

**（c）RL 优化**
学策略 π_φ(a|s)：max_φ E[Σ γ^t r_t]；**不需要气动力学导数**。
论文的评语很克制：一个训练充分的 RL 优化器**据报告能达到梯度法级别的效率而不使用导数**，但训练过程可能耗时〔原文 P59 "a well-trained rl optimizer is reported to achieve"〕。
关键实验事实（Fig. 47）：**大部分减阻在头 5 步内完成**〔原文 P65 "most of the drag reduction is achieved"〕，
且只在 M=0.76、Re=5×10⁶ 训练的策略，可在 M∈[0.72,0.76]、Re∈[5×10⁶,1×10⁷] 上照常减阻〔原文 P65 "can be used for drag reduction at other"〕。
**读法**：头 5 步吃掉 90% 收益 ⇒ RL 的"快"来自**动作先验**（它从不往畸形方向动），不是来自算法天赋。

**（d）合法性门控的统一写法（本白皮书构造，非原文）**：
四种架构都能写成同一句"在线目标 = 收益 − 风险"：

  J(x) = [−ŷ(x) 或 EI(x) 或 E_π[Σγ^t r_t] 或 −‖G(z)−x_target‖²] − β₁(1−S_valid(x)) − β₂·1[d(x, X_train) > d_max]

三项惩罚分别是**合法性**与**外推距离**；β 由你对"愿不愿意让优化器冒险"来定。

**（e）生成式反设计**
给定目标性能 y*，学后验 P(x|y)：conditional GAN / conditional VAE。
论文明确两点：① 反问题在 ASO 里**大多是病态的**——不同形状可以有同样性能〔原文 P66 "ill-posed since different shapes"〕；
② 因此它更适于**低保真概念设计**，而不是交付级最优点〔原文 P59 "could be distinct from the true optimum"〕。
（工业侧同页还有一句："generative inverse design is usually shorted as generative design"，
 并点名 Monolith AI、Altair 把 AI 生成式设计当门面，案例包括**叶轮机械叶片**〔原文 P66 "monolith ai"〕。原文把 "shortened" 写成 "shorted"，照录。）

#### 4. 操作流：怎么选（也是组会上最可能被问的一张表）

| 架构 | 需要的样本 | 在线延迟 | 能带约束吗 | 高维（>30）还行吗 | 何时该用 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 代理式序贯 | 50–1,000 | 秒–分钟（含 CFD） | **天然能**（EI + 约束） | 差〔原文 P60 "does not scale well with the dimensionality"〕 | 预算 ≤ 1,000 次 CFD、d ≤ 20 |
| 交互式 | 10⁴–10⁵ | **毫秒** | 只能显式约束，且**约束错了没人救你** | 中（靠降维救） | 要做产品/前端/汇报演示 |
| RL 优化 | 环境交互 10⁵–10⁷（可用低保真） | 毫秒 | **差**（可调约束是明确短板〔原文 P59 "concerns of rl-based aso include the high training cost"〕） | 差（原文：只演示过少数设计变量的问题） | 流程重复度极高、且约束能用奖励表达 |
| 生成式反设计 | 10³–10⁵ 带标签 | 毫秒 | 以"目标性能"为条件 | 中 | 概念生成、方案海选 |

#### 6. 审稿人批判

1. **Table 4 只给"设计变量数/代理类型/目标"，不给 CFD 次数与最终收益**：于是"17 维 Kriging"与"108 维 Kriging"看起来一样可行，
   而真实差别（收敛是否失败、多少样本）全被抹平——**这是综述表格的通病，本讲 §2 已经替你补了一条分界线**；
2. **"交互式"没有一句成本核算**：10^5 样本的 RANS 训练要多少核时？论文只报推理精度不报训练账，
   这正是 Abstract 里承认的"ML 训练成本高"〔原文 P1 "practical large-scale design optimizations remain"〕在正文里被淡化的地方；
3. **RL 一节只给成功案例**（超临界翼型 3 个 Hicks–Henne 变量），没有任何失败案例或"多少维就崩"的边界；
4. **生成式反设计与优化被并列在"优化架构"里，但它们解决的问题不同**：一个是"给性能求形状"，一个是"给约束求最优形状"；
   并列会误导读者以为生成式设计可以做最优化。

#### 9. 自测 10 题（2 选 + 2 填 + 6 答）

1. （选）代理式序贯优化的"加点准则"最本质的作用是：A 让模型更大 B 决定下一次昂贵 CFD 花在哪儿 C 替代优化器 D 减少设计变量

3. （填）论文 Table 4 里，设计变量 ≤17 的工作几乎都用 __________；跳到 30 维时换成了 __________。

5. （答）为什么说"过滤闸门"是序贯优化的必需品？用一句话 + 一个公式回答。
6. （答）把"交互式 4,000×"与你的"100,000×"放在同一口径下比较，写出各自的分子与分母，并判断是否可比。

8. （答）生成式反设计为什么天生不适合交付级最优点？用一个反例说明（同一 C_D 可以有几种外形）。
9. （答）若明天只能给你的平台加**一个**功能来提高可信度，你加哪个？说清输入输出与判据。
10. （答）批判：为什么"旗舰成果图不给坐标轴含义"是学术不端边缘？你会怎么给 Fig. 46 补三行 caption？

**答案要点**：1-B；2-B；3-Kriging、ANN；4-头 5 步、0.76、5×10⁶；
5-因为不准确代理会把新样本加到畸形区（P61 原话），公式 J 里减 β₁(1−S_valid)；

9-外推门控（最近邻距离 + 覆盖率）——因为它直接决定用户会不会拿错设计去加工；
10-例：补"横轴：优化迭代步；纵轴：C_D 相对基准的变化；数据源：RANS 135,108 样本训练，留出 47,967；推理延迟 1.85 ms（服务端）"。

#### 10. 一句收口

> **换代理省的是次数，换架构省的是数量级；
> 但你必须先能报出自己的训练账本，否则"交互式"只是把成本从看得见的地方挪到看不见的地方。**
